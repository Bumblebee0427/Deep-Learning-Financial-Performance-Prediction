# 训练集内部模型基准（未使用测试集）

运行 `python benchmark_models.py --all` 可重跑。它为每个模型启动独立进程，以控制内存占用；也可用 `--model <名称>` 单独运行，再用 `--summarize` 重建排序表。唯一的数据输入是 `train.csv` 和既有的 `audit_outputs/split_ids.csv`（仅用于校验划分）。代码不会打开 `test_individual.csv`。

所有模型使用与初始审计完全相同的 80,000/20,000 行划分（`random_state=42`），且调用同一个 `score_predictions()`。`Id` 仅写入结果以便逐行对齐，从不进入特征矩阵。类别列在训练折填补并做 one-hot 编码，数值列在训练折用中位数填补。Ridge 和神经网络还对数值特征做 `arcsinh` 及标准化，参数只来自训练折；神经网络的目标也使用基于训练折的 `arcsinh` 缩放。这里没有搜索超参数。

训练时间包含训练折特征预处理与模型拟合，不含 CSV 读取和验证集预测；受系统负载影响，重跑时间可能变化。完整数值见 [`comparison.csv`](comparison.csv)，每个模型的参数、逐目标得分、时间和范围检查见对应的 `*_metrics.json`。

## 观察

- **最难的目标：** `Q0_EBITDA` 与 `Q0_OPERATING_INCOME`。最佳综合模型 LightGBM 在这两个目标上的 sMAPE 分别为 60.35% 与 58.89%，而其他多数目标约为 12%–36%。LightGBM 在验证集中对这两个目标分别有 1,678 行和 1,635 行预测符号与实际相反；这些样本的单项 sMAPE 为 200%。`Q0_GROSS_PROFIT` 是下一难的目标。
- **较强的模型族：** 梯度提升树的综合表现最好，LightGBM 第一、HistGradientBoosting 第二。随机森林和 ExtraTrees 对资产负债表的三个目标尤其强（例如总资产仅 4.37% 和 4.72%），但在利润、费用和收入目标上弱于提升树。这提示后续可以研究按目标选模型或使用这些已保存的验证预测做集成；这里尚未据此选择测试集方案。
- **目标变换的迹象：** 各目标的 99% 分位数与中位数绝对值之比约为 45–182，且多数目标含负值；`log1p` 不适用于这些带符号标签，`arcsinh` 或带符号对数值得做受控比较。神经网络在本轮用了 `arcsinh` 目标变换，表现好于均值基线但不及树模型；由于模型族也不同，本轮不能单独证明变换的效果。
- **明显不合理的预测：** 训练和验证的 `Q0_REVENUES`、`Q0_OPERATING_EXPENSES` 都为正，Ridge 却分别预测出 7,108 和 7,063 个负值；神经网络分别预测出 194 和 351 个负值。Ridge 有 14,231 个预测值落在对应目标的训练集范围之外；神经网络有 636 个，其中 19 个绝对值超过训练目标绝对值的 99% 分位数的 10 倍。四种树模型在此范围检查下均无越界值，但训练标签本身含极端和不合常规的数值，故“未越界”不等于财务上合理。

## 输出与复核

[`validation_truth.csv`](validation_truth.csv) 与 [`validation_predictions/`](validation_predictions/) 中各模型 CSV 都包含同顺序的 20,000 个 `row_index`、`Id` 和 9 个目标列。`row_index` 是原始 `train.csv` 行号，适合后续集成时严格对齐。逐行读取这些文件并重新调用原有 sMAPE 函数后，所有七个模型均复现其记录分数。

这些分数来自一次固定的随机划分，仍可能受到合成数据中未知公司关联的影响；后续可增加交叉验证或分组验证。此阶段没有生成最终提交文件。
本轮按 rubric 使用除 `Id` 外的全部候选特征，包括 `totalRevenue`、`ebitda` 等 Q0 同季度元数据。它们在题目数据中可用，但若实际预测时点尚未获得这些字段，验证分数会高估部署表现；这一可用性问题需要在确定最终模型前核实。
